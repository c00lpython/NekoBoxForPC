# Логирование и стиль кода — глобальное правило

## Логирование: utils/logger.py

Единый декоратор @log_call применяется на ВСЕ функции и методы во всей
кодовой базе (кроме __init__ dunder-методов простых dataclass-подобных
классов без логики — не логировать шум).

Декоратор обязан:
1. Логировать вход в функцию на уровне DEBUG: имя функции/модуля + 
   breadcrumb-цепочка (текущий стек вызовов через декорированные функции, 
   " > ".join(...)) — НЕ логировать значения аргументов, если среди них 
   могут быть токены/пароли/лицензионные ключи (см. license_manager.py — 
   такие функции логируют только факт вызова, не содержимое)
2. Логировать выход на DEBUG: длительность выполнения
3. При исключении — логировать на ERROR: полный traceback + breadcrumb-цепочка,
   ЗАТЕМ ОБЯЗАТЕЛЬНО re-raise (`raise`). Декоратор никогда не глотает 
   исключения молча — иначе программа продолжит работу в невалидном 
   состоянии, что хуже честного краша с трейсбеком.
4. Использовать functools.wraps, чтобы не терять сигнатуру/докстринг 
   декорируемой функции.

## Включение/выключение — БЕЗ изменения кода в дочерних файлах

Используется штатный logging.Logger с уровнями, не самодельный флаг:
- Каждый модуль получает logger через utils/logger.py: get_logger(__name__)
- По умолчанию логгер молчит (WARNING+), потому что DEBUG-сообщения 
  декоратора не проходят порог
- Включение — ОДНА строка в main.py:
  logging.getLogger("upb").setLevel(logging.DEBUG)
- Ни один декорированный файл трогать не нужно для включения/выключения

## Стиль кода

- PEP8 — обязателен для всего нового и изменяемого кода (line length, 
  naming, imports order)
- Каждая функция/метод — комментарий/докстринг с шагами процесса, если 
  логика нетривиальна (больше 5-7 строк содержательного кода). Для 
  однострочных геттеров/сеттеров докстринг не обязателен.
- Внутри сложных функций — инлайн-комментарий перед каждым нетривиальным 
  блоком (например, перед JS-инъекцией, перед структурной сигнатурой 
  в container_discovery.py), объясняющий ЗАЧЕМ, не ЧТО (что видно из кода)

## Производительность — известный компромисс

Оборачивание горячих путей (paintEvent, update_animation, таймеры на 
16-50мс) декоратором добавляет небольшой оверхед даже при выключенном 
логировании (вызов декоратора + проверка уровня). Это принятый компромисс 
ради единообразия и полного трейсинга при отладке. Если конкретный 
горячий путь реально просаживает FPS — обсуждать точечное исключение 
для него отдельно, не менять правило глобально.
